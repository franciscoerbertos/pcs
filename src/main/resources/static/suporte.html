Suporte: DevTools e Status Codes

Use este guia para identificar rapidamente o status code, o payload enviado e a resposta do servidor.

Voltar para o Mockup

Passo a passo no DevTools

PASSO A PASSO Como acompanhar as requisições HTTP
  1. Abra o DevTools (F12) e clique em Network.
  2. No topo do Network, marque Preserve log (para não perder requisições ao recarregar).
  3. Clique em um botão do mockup (ex.: Login Correto).
  4. Na lista do Network, clique na requisição (ex.: /login ou /enderecos).
  5. Aba Headers: veja o Status Code e headers (ex.: access-token).
  6. Aba Payload: veja o JSON enviado (aparece em POST).
  7. Aba Response: veja o corpo retornado (quando existir).

Status Codes mais comuns

Código Classe Significado Quando ocorre O que observar
200 Sucesso Requisição processada com sucesso. GET retornando dados ou POST com resposta. Veja o Response e headers.
201 Sucesso Recurso criado com sucesso. POST de criação. Verifique o objeto retornado.
204 Sucesso Sucesso sem conteúdo na resposta. DELETE ou atualização sem retorno. Response vazio (normal).
400 Cliente Requisição inválida. JSON errado ou campo faltando. Confira Payload e validações.
401 Cliente Não autenticado. Credenciais ou token inválidos. Verifique login/token.
403 Cliente Acesso proibido. Usuário sem permissão. Ver regras de autorização.
404 Cliente Recurso não encontrado. Endpoint inexistente. Confira URL e método.
409 Cliente Conflito de estado. Cadastro duplicado ou regra de negócio. Veja mensagem de erro.
415 Cliente Tipo de mídia não suportado. Faltou Content-Type: application/json. Corrigir headers.
422 Cliente Entidade inválida. Erro de validação de campos. Veja mensagem de validação.
500 Servidor Erro interno do servidor. Exceção no backend. Ver log do Spring.
503 Servidor Serviço indisponível. Servidor fora ou sobrecarregado. Tentar novamente.
